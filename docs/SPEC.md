# Voice Check Bench — Spec

## Goal
A local web app that records a voice in the browser, measures what makes it unclear (level, noise, hum, tone balance per octave, sibilance, consistency), guides the user through a fixed test session, and suggests ReaPlugs settings (ReaGate, ReaEQ, ReaComp) for Elgato Wave Link. A Python tool writes those settings straight into Wave Link's `Settings.json`.

The behaviour reference is the working single-file prototype: `docs/prototype/voice-check.html`. Port it; do not redesign the analysis. Where this spec and the prototype disagree, this spec wins.

## Non-goals
- No backend, accounts or cloud storage. Everything stays in the browser (IndexedDB + localStorage).
- No server rendering. Plain Vite SPA served on localhost.
- No chart library: the band chart is a hand-written SVG component.
- No MP3/WAV export of takes (may come later).

## Stack
- Vite 8, React 19, TypeScript 6 (strict), MUI 9 (`@mui/material`, `@mui/icons-material`, Emotion), Tailwind CSS 4 (`@tailwindcss/vite`), zustand 5, Vitest for unit tests, ESLint 10 flat config.
- MUI + Tailwind coexist through CSS layers: `@layer theme, base, mui, components, utilities;` declared first, `StyledEngineProvider enableCssLayer`. Tailwind is used for layout/spacing utilities; MUI for components and the theme. Do not restyle MUI internals with Tailwind.
- Theme (visual language of andradev.io, see `src/theme.ts`): MUI `createTheme` with `cssVariables` and `colorSchemes` light + dark, default follows the system. JetBrains Mono for everything. Accent olive `#b4b96b` (primary; light mode uses a deeper `#7d8233` for contrast on white). Light: white background, text `#222`. Dark: background `#121212`, surfaces `#222`, text `#f5f5f5`. Status: success/warning/error from the theme; take B = info. Flat: no shadows, 1px dividers, pill buttons and chips, inputs radius 15. Headlines: uppercase, weight 800, two lines where the second line is in the accent color (`<TwoToneHeading first second />` in components/common).

### Data model
`Take = { id: number (Date.now), name, session: string ('s<ts>' or 'free'), step: 'c2'|'c8'|'c15'|'fx'|null, device: string, sampleRate, samples: Float32Array, created: ISO }`; in memory also `analysis`.
Exported settings JSON (consumed by the Python tool): `{ basedOn, speechDbfs, noiseDbfs, gainHint, noiseHint, dist, lowcut, gate:{threshold,attack,hold,release,hysteresis,wet,dry}, eq:[{type:'Low Shelf'|'Band'|'High Shelf',freq,gain,bw,why}], comp:{threshold,ratio,attack,release,knee,wet,limit}, deess }`.

### Wave Link storage format (for tools/)
`%LOCALAPPDATA%\Packages\Elgato.WaveLink_g54w8ztgkx496\LocalState\Settings.json` → `MixerConfiguration.InputSettings[<input with PCM_IN>].AudioPluginConfigurations[]`. `ParameterState` = base64 FXP (`CcnK`).
- ReaGate/ReaComp: `FxBk` bank, 156-byte header, then inner `FxCk` program: 56-byte header then 19 big-endian floats. ReaGate: 0 threshold (linear amp), 1 attack ms/500, 2 release ms/5000, 4 hold ms/1000, 9 dry amp, 10 wet amp, 12 hysteresis amp. ReaComp: 0 threshold amp, 1 ratio (r-1)/99, 2 attack ms/500, 3 release ms/5000, 11 wet amp, 17 limit output 0/1.
- ReaEQ: `FBCh`, 156-byte header, big-endian int32 chunk size, chunk little-endian: int32 version (33), int32 band count, per band `int32 type (0 low shelf, 1 high shelf, 8 band), int32 enabled, f64 freq Hz, f64 gain linear, f64 bandwidth oct, u8 flag`, then a 20-byte tail kept as is.
- Verified by decoding values set in the UI. Round-trip (decode → encode unchanged) must be byte-identical.

## Noisy-room mode (v0.2)
Goal: the best result a person can get in a bad room (servers, fans, AC, street) without changing the room. A bad room is the normal case, not an error.

**Diagnosis (audio/analyze.ts, audio/diagnose.ts).** From the existing silence window and speech spectra:
- `speechBands` / `noiseBands`: average power per BANDS entry (divide summed spectra by block count so both are on the same scale), `bandSnr = speechBands - noiseBands`.
- `tones`: peaks in the silence spectrum 90 Hz–8 kHz at least 8 dB above the local median (±1/3 octave), merged within 3 %, strongest first, max 6. Mains (50/60/100/120 Hz ±2 %) are reported by `hum`, not here.
- `noiseKind`: quiet (noise < -60 dBFS or SNR ≥ 30) · hum (strongest hum peak ≥ 10 dB and no strong tones) · tonal (≥ 1 tone ≥ 12 dB) · broadband.
- New checks: `tones` (warn ≥ 1 tone ≥ 12 dB; fix: notch suggestions + aim the back of the mic at the source) and `bandsnr` (bad when the voice bands 640 Hz–5 kHz average SNR < 15 dB, warn < 25).
- `bestControl` weights SNR more when the room is noisy: penalty `max(0, 40 - snr) / 2` becomes `max(0, 40 - snr)` when any control take has SNR < 25.

**Suggestions (settings/suggest.ts).** `noisyRoom = snr < 25`. Then:
- chain `['ReaFIR', 'ReaEQ', 'ReaComp', 'ReaGate']` (quiet room: `['ReaGate', 'ReaEQ', 'ReaComp']`).
- `noiseReduction` = ReaFIR plan: add ReaFIR first; Mode **Subtract**; FFT size 4096; stay silent and tick **Automatically build noise profile** for ~3 s, then untick; start with the curve lowered so reduction ≈ 10–12 dB (stronger for SNR < 15) and back off if the voice turns watery/robotic. Alternatives: Elgato Noise Removal, Voice Focus (ai-coustics), NVIDIA Broadcast.
- ReaEQ: notches for each tone ≥ 12 dB (type Band, bw 0.1 oct, gain -6 to -12 dB by tone strength, max 3 notches); no boosts in bands whose `bandSnr` < 12 dB (clamp that band's gain to ≤ 0); high shelf capped at +2 dB; if the 5–16 kHz bands have SNR < 10, a high shelf of -2 to -4 dB instead.
- ReaComp: ratio 2.5, threshold `speechMed - 4`, makeup aims for -20 dBFS but never more than `-(noise after reduction) - 45` so the room is not pumped up.
- ReaGate as soft expander: threshold = estimated noise after reduction + 6 dB (estimate: `noise - 10`), dry -10 dB, hold 200 ms, release 300 ms.
- `noiseHint` stays; text/JSON include the chain, the ReaFIR steps and alternatives.

**UI.** Setup: live "Room" reading next to the meter while silent (quiet / some noise / noisy by level), and a placement tip built from the mic profile (cardioid: "point the back of the mic at the loudest noise source"; supercardioid: "put the noise at the mic's sides, ~125° off-axis"; omni/unknown: "move the mic closer to you and away from the noise, the pattern won't reject it"). Steps: same tip under the lead on control steps. Results: a "Room noise" panel (noise level and kind, tones list as chips, per-band SNR bars with 10/20 dB guides) and, when the session has a processed take, a "Before / after" card: SNR raw control (same distance) → processed, and voice-band SNR change. Suggested settings render the chain order and the ReaFIR steps as a numbered list.

**Tool.** No format change: notches are ordinary ReaEQ bands; ReaFIR is added and set up by hand.

## Generic mics + mic profile (v0.2)
The app is not tied to any mic. All copy is generic ("speak on-axis", "the mic", "the capsule"); no model names in UI text, checks or suggestions.
- `MicProfile` (types.ts): free-text model with a suggestion list (Fifine K688, Fifine K669, Shure SM58, Shure SM7B, Shure MV7, Rode PodMic, Rode NT-USB, Audio-Technica AT2020, AT2005USB, Blue Yeti, HyperX QuadCast, Elgato Wave:3, Samson Q2U, Maono PD200X, Other), kind, pattern, address. Picking a known model pre-fills kind/pattern/address (src/mics/catalog.ts); the person can change them.
- Setup screen: "Your microphone" card before the mic access card. Saved in localStorage `vcb-mic`. Copied onto every new take (`take.mic`).
- Advice that depends on the mic: address → "speak into the top" (end) vs "speak into the front side, where the logo is" (side) vs "point the capsule at your mouth" (unknown); pattern → placement tip (above); kind → condenser adds "condensers pick up more of the room: stay closer and lower the gain" to the noisy-room hint.
- Learning from people with the same model (later): each take stores `mic`, and Results offers "Copy anonymized summary" (JSON: mic profile, analysis numbers per take, suggestion values; no audio, no device names, no dates). How to aggregate (GitHub, a small API) is decided later.

## Community results via GitHub issues (v0.3)
Contract: `src/community/types.ts`. No server.
- **Share:** Results → "Share with the community" opens `https://github.com/<COMMUNITY_REPO>/issues/new?template=mic-result.yml&title=Mic result: <model>&summary=<minified CommunitySummary JSON>` in a new tab (issue form pre-fill by field id). The person reviews and submits with their own GitHub account; the page says that the issue is public. Disabled when the mic model is empty. If the URL would exceed ~7500 chars, round numbers harder / drop tones beyond 3 / drop rel then fall back to copy + open the blank form.
- **Issue form** `.github/ISSUE_TEMPLATE/mic-result.yml`: label `mic-result`; fields: summary (textarea, render json, required), notes (optional textarea: room, setup), consent checkbox ("I understand this issue is public").
- **Aggregation:** `src/community/aggregate.ts` (pure: parse issue bodies → valid CommunitySummary list → CommunityIndex; rejects malformed/out-of-range, dedupes identical summaries, ignores reports without a model) + `tools/community/aggregate.ts` (run with `npx tsx`; fetches issues with the label through the GitHub REST API using GITHUB_TOKEN when set, paginates, writes `public/community/mics.json`). GitHub Action `.github/workflows/community.yml`: after the review on mic-result issue events, every 6 hours and on demand; runs the script; commits the JSON if it changed.
- **Display:** the app fetches `${BASE_URL}community/mics.json` (fail soft). Setup "Your microphone" card: when the model matches, "N people with this mic: typical SNR …, best distance …". Results: a "People with this mic" card comparing your best raw control (SNR, deviations per band) with the community median, and their median EQ.
- **Automatic checks (v1.2):** `.github/workflows/community.yml` job `review` runs `tools/community/review.ts` on mic-result issue events (opened, edited, reopened, labeled, unlabeled; not for the bot's own actions). All issues are reviewed in issue-number order (`src/community/review.ts`, pure), so the checker and the aggregator always agree: a hand-set `rejected` label wins; an unparseable Summary, one without a raw control take or a model without letters/digits → `invalid`; the same Summary (sorted-key hash) as a counting issue → `duplicate`; else `accepted`. The model is matched to known mics (`src/community/micMatch.ts`): `tools/community/aliases.json` aliases, exact `micKey`, then fuzzy (1 edit from 5 chars, 2 from 8, never when the digits differ; or a ≥4-char key with a digit inside the other) unless the pair is listed in `distinct`. A newer report by the same author for the same mic replaces the older one in the stats. Only the target issue changes: exactly one of `accepted`/`invalid`/`duplicate`, one bot comment (edited in place, hidden marker `<!-- vcb-review -->`, only the mic model is quoted from the issue, as a code span), invalid/duplicate closed as not planned, reopened when accepted again only if the bot closed it. The labels it sets never change a verdict.
- **Votes (v1.2):** 👍 reactions on an issue are its votes. Each mic in `mics.json` lists `solutions` (one per counted report with a suggestion: votes, style, noisy room, best raw control SNR and distance, SNR gain, suggestion without free text), most votes first, then newest. Reactions do not trigger workflows, so the aggregate job also runs every 6 hours.

## Plain language (v0.5)
Audience: people who know nothing about audio. Every screen leads with plain words and actions; numbers and terms are optional detail.

**Message keys, not text.** Framework-free modules return `{ key: string; params?: Record<string, string | number> }` (type `Msg`, src/plain/types.ts). The UI renders them with i18n (v0.6). English source strings live in `src/i18n/locales/en.json`.
Engine text is `Msg` too (v0.6): `Check` has `titleMsg`/`valueMsg?`/`detailMsg`/`fixMsg?`; suggestion hints, ReaFIR steps, alternatives and EQ reasons, `failureHint`, mic tips and store status lines (`StatusMessage { msg, error }`) return keys under `engine.*` (`<locale>/engine.json`), numbers as params formatted in the string (`{{v, number(…)}}`); the downloaded .txt sheet and settings JSON stay English (`englishText`), "Copy as text" is localized.

**Clarity score (src/plain/score.ts)** — `clarityScore(a: Analysis): { score: number; main: 'noise' | 'level' | 'tone' | 'none' }`. Penalties, then `score = round(clamp(100 − Σ, 0, 100))`:
- noise: `clamp((30 − snr) × 1.5, 0, 45)`; +5 if any tone ≥ 12 dB or hum ≥ 12 dB.
- level: speech median outside [−26, −16] dBFS → `min(15, 2 × distance)`; clipping → +15.
- tone: `min(25, 1.2 × Σ_{bands 1..7} max(0, |dev| − 3))`.
- consistency: spread > 8 → `min(10, 1.5 × (spread − 8))`.
`main` = largest of noise / level / tone penalty (≥ 8), else 'none'.
Headline key by score: ≥ 85 `score.clear` ("Clear and clean") · 70–84 `score.good` ("Good — small things to polish") · 50–69 `score.ok.<main>` ("Understandable, but the room is loud" / "…but your volume needs fixing" / "…but your voice sounds a bit off") · < 50 `score.hard.<main>`. Plus a one-sentence explanation key per headline.

**Three everyday ratings (src/plain/ratings.ts)**, each `{ id, status: Status, label: Msg, explain: Msg }`:
- Background noise — snr ≥ 30 "Quiet" (good) · 20–30 "Noticeable" (warn) · < 20 "Loud" (bad); explain by noiseKind: tonal "A fan or machine is easy to hear." · hum "A low electrical hum is audible." · broadband "A steady hiss or room noise is audible." · quiet "Your pauses are clean."
- Your volume — "Good" · "Too quiet" · "Too loud" · "Distorting" (clipping) from the level/peaks checks.
- Sound of your voice — largest |deviation| over bands 1..8: ≤ 3 dB "Natural"; else by band and sign: boom/warmth high "Boomy" · mud high "Boxy" · body low "Hollow" · definition/presence low "Muffled" · presence high "Harsh" · sibilance high (or harsh S peaks) "Sharp S sounds" · sibilance+air low "Dull" · boom+warmth low "Thin"; prefix "A bit" for 3–6 dB, "Very" for > 6. Explain keys in everyday words ("Too much bass, a little muffled.").

**What to do next (src/plain/actions.ts)** — `nextActions(a, ctx): Action[]`, max 3, `{ id, text: Msg, cost: 'free' | 'minutes', impact: number, how?: 'settings' | 'placement' | 'gain' }`, sorted by impact desc, free before paid on ties, no duplicates:
- noisy (snr < 25): placement tip by mic pattern (impact = noise penalty), "Move closer: about one fist away" (only if best distance > current or not 2 cm), "Switch off fans or machines you can while recording", "Turn on noise reduction with our ready-made settings" (how: settings).
- level: too quiet "Turn the input volume (gain) up a little" · too loud/distorting "Turn the input volume (gain) down a little" (how: gain).
- tone: boomy "Back off a little — bass builds up when you're very close" · muffled "Speak straight into the mic" (address-aware) · sharp S "Angle the mic slightly off to the side of your mouth"; plus "Use our ready-made EQ settings" (how: settings) when tone penalty ≥ 8.
- hum: "Plug your audio interface into a different USB port (back of the computer)".

**Everyday distances:** 2 cm "about a finger's width" · 8 cm "about one fist" · 15 cm "about an open hand" — shown with the number.

**Glossary (src/plain/glossary.ts + `<Term id>` component):** gain, noise, SNR ("how much louder your voice is than the room"), dB, EQ, noise reduction, compressor, gate, sibilance, proximity effect, cardioid — one sentence + an everyday analogy each.

**Results layout:** score ring + headline + explanation → three rating cards → "What to do next" (each with "Show me how" opening the right panel: placement tips, the settings walk-through, or gain help) → collapsed "Show the technical details" containing everything that exists today. Steps/setup/pages use the same plain register (no unexplained jargon; numbers secondary).

## Guided setup with interactive plugin replicas (v0.7)
Goal: show people exactly where to click and what to type, with their own values. No real screenshots of third-party software are shipped; panels are hand-built replicas (SVG/HTML + MUI) that mirror the layout and field names of the real windows.
- **"What do you use?"** (asked at the start of the guide, saved): Elgato Wave Link · OBS Studio · Discord / Teams / Zoom only · NVIDIA Broadcast · Not sure. Not sure → a short explainer and a recommendation (Wave Link users → Wave Link path; otherwise OBS or app-only path).
- **Wave Link + ReaPlugs path (first):** 1) open Wave Link → your mic → Effects (replica of the effects list with toggles, highlighting what to turn on/off and the order); 2) add a plugin (replica of "Add effect" → ReaPlugs entries); 3) one step per plugin in the suggested chain with a replica panel:
  - ReaFIR: mode dropdown = Subtract, FFT size = 4096, "Automatically build noise profile" checkbox with a 3-second "stay silent" cue, curve sketch showing the profile being lowered.
  - ReaEQ: graph with the person's actual response curve computed from the suggested bands (shelf/band/notch formulas), numbered band nodes, band tabs 1..N, fields Type / Frequency (Hz) / Gain (dB) / Bandwidth (oct) filled with the values; the current band highlighted.
  - ReaComp: Threshold slider + value, Ratio, Attack, Release, Knee size, Output mix Wet/Dry, "Limit output" checkbox.
  - ReaGate: Threshold, Attack, Hold, Release, Hysteresis, Wet/Dry.
  Each panel has numbered callouts (① click … ② type …) and a "Done, next" button; a checklist tracks progress; the alternative "apply automatically" path explains `tools/apply-reaplugs.py` (Wave Link closed).
- **OBS path (second):** Audio Mixer → ⋮ → Filters; built-in Noise Suppression (RNNoise), Expander/Noise Gate, 3-Band EQ, Compressor, Limiter with values mapped from the suggestion; option to load ReaPlugs VSTs via the "VST 2.x Plug-in" filter.
- **App-only path:** what to switch on/off in Discord/Teams/Zoom (noise suppression, echo cancellation, auto gain) + the free physical actions.

## Over-processing safety (v0.8)
Real case: following the noisy-room guide, ReaFIR set too strong produced a processed take 18 dB quieter, with the bass gone (−34 dB), harsh presence (+11), 40 % exact-zero samples and 46 gate flips in 20 s — and the app scored it 54 "quiet room" (noise −240 dBFS → SNR 197).
- **Analysis:** noise floor and frame levels are clamped at −100 dBFS (no −240), so SNR stays meaningful; new `zeroRatio` (share of samples inside runs of exact zeros ≥ 10 ms; isolated zeros from 16-bit quantization of a very quiet room don't count) and `gateSwitches` (zero runs ≥ 20 ms that start, per 10 s: each one is the processing slamming shut). Digital silence, not "quiet": a real room never trips them. New check `overprocessed`: bad when zeroRatio > 0.15 or gateSwitches > 12, warn when zeroRatio > 0.05 or gateSwitches > 6; fix: "Noise removal or the gate is too strong and is cutting your voice — reduce it".
- **Processed vs raw comparison** (plain module, used by results and score): when A is a processed take and a raw control of the same session exists, flag: level drop > 8 dB ("your voice got much quieter"), bass loss (boom+warmth deviation drop > 12 dB → "thin"), presence/sibilance rise > 6 dB ("harsh"), and over-processing. Clarity score of a processed take: noise penalty uses SNR capped at 45 and adds an over-processing penalty up to 35 (zeroRatio/gateSwitches) plus 10 per flagged regression; headline `score.overprocessed` ("Too much processing: it's cutting your voice"). Next actions put "turn noise removal down" first.
- **Suggestions:** ReaFIR reduction starts at about 6 dB ("drag the curve down a little — about 6 dB — then listen; stop at the first watery or robotic sound"), never "until the room drops 15 dB". `preferAi = snr < 15`: AI noise removal (Elgato Noise Removal, NVIDIA Broadcast, Voice Focus) is presented first and ReaFIR as the alternative. Gate dry stays −10 dB (never full silence). After noise reduction, a note to raise ReaComp Wet by the level lost (measured in the before/after).
- **Processed take distance:** the processed step records at the best control distance; the step and the guide say so explicitly ("same distance as your best take: 2 cm").

## Voice goals (v0.9)
People decide what "good" means for them. Nothing is judged against a single curve anymore.
- **Goal** `VoiceGoal = { style: 'natural' | 'warm' | 'clear' | 'bright'; perceived: PerceivedIssue[] }`, `PerceivedIssue = 'nasal' | 'muffled' | 'boomy' | 'thin' | 'harsh' | 'sharpS' | 'dull'`. Saved in localStorage `vcb-goal` (try/catch), editable on setup ("What do you want your voice to sound like?" + "How does your voice sound to you? (optional)") and on results ("Change goal" re-scores instantly; no re-recording).
- **Target curve:** `targetDeviations(rel, goal)` = deviations(rel) minus the style offset per band (dB; bands rumble, boom, warmth, mud, body, definition, presence, sibilance, air):
  - natural `[0, 0, 0, 0, 0, 0, 0, 0, 0]` (today's reference)
  - warm `[0, +3, +2, 0, +1, 0, -1, -1, -1]` (radio / podcast: more bass and body)
  - clear `[0, -1, -1, -1, 0, +2, +3, +1, +1]` (cuts through games and calls)
  - bright `[0, 0, -1, 0, 0, 0, +1, +2, +3]` (more sparkle on top)
  Same ±3 / ±6 dB tolerances around the target. Every consumer of deviations (diagnose band checks, plain ratings/score/actions, suggest EQ, bestControl, charts) takes the goal; charts label the zero line "your target".
- **Perceived issues** (what the person hears) combine with what is measured:
  - nasal ⇔ body (640 Hz–1.25 kHz) or definition (1.25–2.5 kHz) above target by > 1.5 dB · muffled ⇔ mud high or presence low · boomy ⇔ boom/warmth high · thin ⇔ boom+warmth low · harsh ⇔ presence high · sharpS ⇔ sibilance high or sibP95 > −6 · dull ⇔ sibilance+air low.
  - Confirmed by measurement → priority in "What to do next" and the full EQ correction; a new EQ band for nasal: Band ~1000 Hz (centre at the larger of body/definition excess), −2 to −4 dB, bw 1.0.
  - Not confirmed → an honest note ("We didn't measure this, but you hear it — here's a gentle tweak") and a gentle correction of 1.5 dB in that direction (never more), marked as "by ear".
- Community summaries add `goal.style` (not perceived) so stats can be split by style later.

### Profiles revision — Wave Link file round trip (supersedes the "Tool" bullet above)
Wave Link keeps all plugin states in `%LOCALAPPDATA%\Packages\Elgato.WaveLink_g54w8ztgkx496\LocalState\Settings.json` (format in "Wave Link storage format"). The web app edits that file directly, in any browser:
1. **Upload** (file input; the page shows the exact path to paste into the file dialog). Validate it is a Wave Link settings file (MixerConfiguration.InputSettings with an input that has AudioPluginConfigurations) and pick the mic input (PCM_IN; let the person choose if several).
2. **Read current state:** decode every plugin on that input (ReaGate/ReaComp FxBk floats, ReaEQ FBCh bands, ReaFIR blob kept opaque, Elgato effects' BypassState) — TypeScript port of tools/apply-reaplugs.py, tested byte-identical on round trip against the real file (local `_test/wavelink-settings.json`, git-ignored).
3. **Preview the diff** in plain words + values ("ReaEQ: 4 bands → 6", "ReaComp Threshold −34 → −28 dB", "Turn off: Elgato EQ").
4. **Download** the adjusted `Settings.json` (only ParameterState/BypassState of the touched plugins change; formatting — CRLF, indent, .NET-style escaping — preserved) and, in the same click, the untouched original as `Settings.before-<date>.json`. Instructions: quit Wave Link from the tray icon, replace the file in that folder, start Wave Link. Undo = copy the backup back. **Profiles** store the decoded plugin states (including the opaque ReaFIR blob once it has been configured in Wave Link) plus the suggestion/goal/validation data; applying a profile = upload the current file → download it with the profile's states. The Python tool stays for people who prefer it.

## Refinement loop (v1.1)
Real case: applying the suggestion made the take worse (35 → 0: 15 cm chosen as "best", gate −41 dB closing on the processed voice, ReaFIR too strong, bass cut twice, Wet +2 dB). The app must evaluate every applied setting and refine until it improves.
**Engine fixes (prerequisites):**
- bestControl in a noisy room (any control SNR < 25): SNR dominates — score = 0.5 × tone excess + 1.5 × max(0, 40 − snr); in quiet rooms unchanged. Real data (2 cm SNR 16.3 boomy, 15 cm SNR 7.9) must pick 2 cm.
- Gate with noise removal in the chain: threshold = round(clamp(speechMed − 30, −72, −45)), dry −10, hysteresis −6 (the gate sees the processed, quieter voice); without noise removal keep today's rule.
- bandSnr / noiseBands: noise band floor −100 dBFS-equivalent and bandSnr capped at 60 dB.
- Distance check: a processed take whose distance differs from `applied.dist` (the raw reference's distance only when the applied settings carry none) gets a warning and is NOT used to judge the settings. The processed take is always compared with the raw control at the distance it was actually recorded at (its own name, else fxDist). Results offer both ways out: "Record again at {{dist}}" and "Make settings for {{actual}}" (clears the guide override, keeps fxDist = actual, opens the guide, whose suggestion is built from the raw take at that distance).
- Processed step: under the ruler, "Where are you recording?" (2 / 8 / 15 cm toggle = fxDist, disabled while recording). When `applied` exists and was made for another distance, an info alert says so and that the results will offer settings for the chosen distance.
- Too loud (regression `tooLoud`, replaces `quieter`): processed peak ≥ −1 dBFS or speech median above the level check's good range (−16 dBFS). Constants shared from diagnose.ts (`LEVEL_GOOD_MIN/MAX`, `TARGET_SPEECH_DB` = −21, the middle of the good range, `PEAK_WARN_DB`).
**Loop:**
- `applied` (store, localStorage `vcb-applied`): set by `markApplied` when the person downloads/saves an adjusted Wave Link file, applies a profile, or confirms "I applied these" at the end of the guide / suggested settings. Each new processed take copies `applied`.
- Evaluation of a processed take with `applied`: improved when fxScore ≥ rawScore + 5 and no regressions; else `refine(raw, fx, applied, goal): Refinement` (pure, src/plain/refine.ts):
  - chopped / zeroRatio > 0.05 → if noiseRemoval = reafir: switch to 'ai-elgato' (attempt ≥ 2) or "lower ReaFIR reduction by half" (attempt 1); AI route: "lower the noise remover's strength or try Voice Focus; pauses should sound quiet, not dead silent". Gate: threshold − 10 dB (min −72), or off (Wet −100, Dry 0) if still chopped on a later attempt — skipped when the gate already passes everything (off, or Dry ≥ −1 dB); then with no noise removal: "another effect in Wave Link is cutting the sound; switch effects off one at a time".
  - gateDoubled (any non-improved take): ReaGate adds Wet and Dry, so Wet open with Dry > −10 dB passes the voice twice (+6 dB at 0/0) → Dry −20 (`GATE_SOFT_DRY_DB`). Never write Wet and Dry both at 0 dB to mean "gate off" (spike finding, `spike/vst2-host/FINDINGS.md`).
  - tooLoud → comp wet −= ceil(fx speech − gate fix − (−21)), at least 3 dB minus the gate fix when the peak clipped, floor 0 (the dB the doubled-gate fix removes count first).
  - quieter (levelDrop ≥ 4, never with tooLoud) → comp wet += min(round(levelDrop), floor(−21 − fx speech)) (cap 18; skipped when ≤ 0), so it never overshoots the target.
  - thin (bass loss) → move low shelf 150 Hz and the 250 Hz band toward 0 by the measured boom/warmth loss vs raw (never past 0 unless the goal wants more bass).
  - harsh → high shelf and 3.5 kHz band −(presence/sibilance rise × 0.7), min −4. With tooLoud: no EQ change, "harsh from clipping" instead (the harshness is the limiter's distortion; fix the loudness first).
  - stillNoisy (fx SNR < raw SNR + 3 and no other regression) → stronger noise removal: reafir "about 3 dB more" or switch to AI.
  - wrongDistance → dist = `applied.dist`, no other change (re-record there, or make settings for the recorded distance).
  - changeApproach after 3 attempts without improvement: recommend AI noise removal + physical actions (placement, closer), stop tweaking numbers.
- **UI:** results for a processed take show an "Attempts" timeline (Attempt N: raw → fx score, ✓/✗) and, when not improved, a "Let's refine" card: the plain list of changes + "Apply refined settings to Wave Link" (dialog with the refined plan; marks applied with attempt+1) + guide link for by-hand changes + "Record again with effects" (goes to the fx step at `dist`). When improved: "It worked" + Save as profile. Copy plain, en + pt-BR.

The engine also keeps the last 60 s (`history.ts`) and segments split at each change, summed over their whole length (`segments.ts`, via `tracker.ts`) for the desktop UI; the web panels don't show those.

## Desktop app (v2.0)
A Windows app that runs the person's real Wave Link plugins live on the raw mic. Every change is heard and measured right away. Once it sounds right, the app writes the result into Wave Link. Proven by the spikes in `spike/vst2-host/FINDINGS.md` and `spike/vst3-probe/FINDINGS.md`.
- **Why:** the web live mode only sees what Wave Link outputs, and its numbers vanish when you stop talking. The app owns the chain, so:
  - raw and processed are sample-aligned (known delay, no guessing);
  - changes apply instantly;
  - export is byte-exact.
- **Non-goals (v2.0):**
  - macOS and Linux.
  - The app's own DSP, or a virtual audio device.
  - Wave Link's built-in effects (VoiceFocus, WaveEQ, WaveCompressor, WaveExpander). They have no plugin file, so they are shown as "can't preview, kept as is".
  - Changing Wave Link while it runs. It has no control API, so Settings.json is written only with Wave Link closed.
- **Stack:**
  - Tauri v2 in `desktop/`, with the Rust side in `desktop/src-tauri/`.
  - The frontend is this Vite app (same `src/`); desktop screens render only when `isDesktop()`.
  - Rust: `cpal` (WASAPI shared), own VST2 FFI (from the spike), the `vst3` crate (coupler-rs) for VST3, `libloading`, `serde_json`, `base64`.
  - Windows only, 48 kHz, 480-sample blocks (the WASAPI shared-mode minimum and the Elgato Noise Removal frame size).
- **Engine (Rust, `desktop/src-tauri/src/`):**
  - `host/vst2`: ReaPlugs.
    - State is a JUCE bank (`CcnK…FBCh`, fxVersion 1100, 1 program).
    - ReaGate and ReaComp: 19 big-endian float params via set/getParameter.
    - ReaEQ and ReaFIR: `effGetChunk(0)`.
    - Re-read the parameter list after each state load, because ReaEQ changes numParams.
    - ReaFIR re-encodes its noise profile on every save: compare it by parameters, never by bytes.
  - `host/vst3`: Elgato effects.
    - State is JUCE `VC2!` XML wrapping `<IComponent>` (JUCE base64 of `IComponent::getState`).
    - PluginId is the JUCE uniqueId derived from the Audio Module class id.
    - Plugins live on one thread with a Win32 message loop.
    - After a state load or a bypass change, wait ≥ 120 ms before trusting Noise Removal's output.
    - Noise Removal adds a 480-sample delay it doesn't report, but only while its own bypass is off (bypassed, it passes audio through undelayed); the engine adds it to the known chain latency in that case.
  - `chain`: the mic input's effects in Wave Link order.
    - Hostable effects are instantiated from their stored states.
    - Per-plugin bypass mirrors Wave Link `BypassState` and the plugin's own bypass, and export writes both consistently.
    - Bypass in the preview is delay-compensated: a bypassed slot still delays the audio by its latency, so the chain latency (and the raw/processed alignment) stays constant while toggling effects for A/B (task 39).
  - `audio`:
    - Raw mic in → chain → monitor out. The default input is the one named "Wave XLR"/"Mic In" (any input can be picked); the default output is the device named "Headphones".
    - Parameter changes go through a lock-free queue and apply between blocks.
    - Monitor: Processed / Raw / Off. Output gain starts at −10 dB.
    - Counters for underruns and processing time.
  - `stream`: every 100 ms, sends the UI that period's raw and processed blocks (mono float32, already aligned by the chain latency) plus meters, over a Tauri channel.
  - `wavelink`: reads Settings.json (read-only) and lists inputs and their chains. Export runs these steps:
    1. Show the diff and ask for confirmation.
    2. Back up to `Settings.backup-<date>.json` (same naming as the web flow).
    3. Close Wave Link: close its window and wait up to 10 s; force it only after a second confirmation.
    4. Write Settings.json.
    5. Start Wave Link again.
    6. Re-read the file and verify every changed `ParameterState`.

    Tests only ever touch copies.
- **Offline render (`render`):** a recorded raw take (mono f32, 48 kHz) runs through the person's real mic chain faster than real time, as often as needed with different settings, without audio devices.
  - Commands: `render_open` (its own plugin instances, from Settings.json read-only; replaces an open session), `render_set_param` / `render_set_bypass` / `render_load_state` (same as the `audio_*` twins), `render_run` (raw little-endian f32 body in, the same out), `render_export_states`, `render_close`. One session at a time. It may run while the live engine runs: each has its own instances, only the host thread is shared (measured in one process: 0 underruns or overruns, renders identical to the ones without the engine).
  - A run: wait for VST3 changes to settle and for Noise Removal to follow its bypass, reset every plugin (VST2 suspend/resume, VST3 deactivate/activate), 1 s of silence, then the take and a tail in 480-sample blocks. The chain latency is removed, so the output has the input's length and lines up with it. It is not clamped.
  - Repeatable: the same samples and settings give bit-identical output, whatever ran before. Without the reset, ReaFIR and Noise Removal keep state that silence does not clear (runs differed by up to 0.5).
  - Noise Removal follows a bypass change on the clock. After a while bypassed it takes up to ~0.5 s of wall time, which a fast run never gives it: it would pass the whole take through. So a run sends it noise blocks 10 ms apart until it really denoises (or really passes through), for up to 3 s.
  - Measured (19.9 s take): the stored chain renders in 0.24 s (≈ 83× real time), every hosted slot on in 0.87 s (≈ 23×). Alone: De-Esser ≈ 59×, Noise Removal ≈ 79×, ReaFIR ≈ 108×, the others 500× or more. The first run after a VST3 bypass change takes 0.1–0.6 s.
  - Headless: `desktop/src-tauri/examples/render_cli.rs` is the same session over line-delimited JSON on stdin/stdout (open, set_param, set_bypass, load_state, run through raw f32 files, export_states, wavelink_read, close), so the TS tuner can drive the real chain without the app (`tools/tune-real/`). It reads Settings.json only through `VCB_WAVELINK_SETTINGS` (pointed at a copy).
- **Live analysis (framework-free TS, `src/desktop/`):** reuses `computeLiveMetrics` with the known lag (no `LagTracker`), and adds:
  - **Hold:** for each side, the last values measured with ≥ 1 s of speech stay on screen during pauses, marked "last heard N s ago". Pause noise keeps updating.
  - **History:** a 60 s scrolling chart of raw and processed speech level and of pause noise (one point per 500 ms), with a marker at every setting change.
  - **Segments:** each setting change starts a segment. There is a summary per segment and one since Start: median speech level, pause noise, clipped frames, dead-silence share, and tone vs goal over all speech frames of the segment. "Before/after this change" is then a pair of rows.
  - The same hold + history goes into the web live mode (`src/live/`), fixing "it resets when I stop talking".
- **Tuning:**
  - Each plugin card has sliders for the values the guide already uses:
    - ReaGate threshold, hold, release, Wet and Dry;
    - ReaComp threshold, ratio, attack, release and Wet;
    - ReaEQ bands;
    - Elgato Noise Removal strength (VAD Threshold) and on/off;
    - ReaFIR on/off.
  - "Open plugin window" opens the plugin's own editor, for example to capture a ReaFIR noise profile.
  - "Try this" advice turns live metrics into concrete changes, using the refine rules and constants (`src/plain/refine.ts`, `src/audio/diagnose.ts`):
    - too loud → Wet down until speech sits at −21 dBFS;
    - doubled gate → Dry −20;
    - dead silence → noise removal lower, or gate threshold −10 (noise mode "Keep it natural" only);
    - noisy pauses (pause noise above −50 dB) → Noise Removal strength +20, capped at 100 (noise mode "Remove as much as possible" only; it replaces the dead-silence advice);
    - too quiet → Wet up (cap 18);
    - tone → the guide's EQ moves, only for what the person hears (below).
  - **Your sound** (card beside "Try this", "Advice follows this"): chips for Style (natural / warm / clear / bright, the stored goal), What you hear (boomy, muffled, thin, harsh, sharp S, dull, pick any; "Sounds good" clears them; no "nasal", since no EQ band answers it), How much processing (Light / Medium / Strong) and Background noise (Keep it natural / Remove as much as possible). Style and What you hear are the shared voice goal; amount and noise are stored in `vcb-tuning-prefs`. Footnote: tone changes only for what is picked under What you hear; level and noise advice always run.
  - **Tone advice is perceived-only:** a ReaEQ band moves only when the person picked the issue its direction means (boomy = boom/warmth high, thin = low, muffled = mud high or presence low, harsh = presence high, sharp S = sibilance high, dull = sibilance low) and it is more than 1.5 dB off the goal that way. Nothing pushes a voice toward the average curve on its own. Move = 0.7 × deviation, rounded to 0.5 dB, at most the amount's step (Light 2, Medium 4, Strong 6 dB), inside the guide's range.
  - **Tone trend:** a single 4 s window swings 2–8 dB and can flip sign, so tone advice uses the trend of the fresh windows (last 30 s, each window once, started over after every change and on a new style). A band counts when its windows span ≥ 11 s (~15 s of talk), it has ≥ 8 readings and ≥ 80 % of them share the sign of their median; the median is the deviation. The row says "Seen in N s of talk, same direction every time".
  - One tap applies a change live; each change has its own Undo. After a change, advice waits one live window (4 s of stream) so it never judges audio from before the change.
  - **Did it help?** After Apply a card shows "Applied: <change>", then "Listening to the change… N s" on the stream clock until those 4 s have passed, then "Does it sound better?" with Better / Same (dismiss) and "Worse, undo" (undoes the change and blocks that move, the same value in the same direction, for the session). Only the latest Apply asks; loading a chain clears the blocks and the trend.

- **Start points:** the current Wave Link chain (default), a saved profile, or the web app's suggestion (SuggestionJson → plugin values through the existing `src/wavelink` mapping).

### Tune from a recording (desktop)
The live "Try this" advice judged 4 s windows whose readings swing 2–8 dB, level-matched the tone with a mean that one deep low-cut skews by about 4 dB on every other band, and moved a 10 kHz shelf for a 5–10 kHz problem. It did not make a mic sound better. The tuner replaces guessing with a closed loop on one recording. Code: `src/desktop/tune/` (framework-free), public API in `index.ts`.
- **Flow:** the person records one raw take (about 25 s: 3 s quiet, then speech) and says what they want. `tune({ take, goals, chain, render })` renders that take through the real chain with candidate values, measures the whole take, and keeps a change only when the measurement says it helped. The result is the kept changes, before / after summaries, the final render, the renders used, the goals it could not reach, and a debug log. No change at all is a valid result.
- **Inputs:**
  - `take`: mono 48 kHz raw mic.
  - `goals: { use: 'streaming' | 'calls' | 'recording'; style: VoiceStyle; bothers: Bother[]; amount: 'light' | 'medium' | 'strong' }`, `Bother = 'roomNoise' | 'boomy' | 'muffled' | 'boxy' | 'nasal' | 'thin' | 'lacksBody' | 'lacksClarity' | 'lacksPresence' | 'harsh' | 'sharpS' | 'dull' | 'tooQuiet' | 'unevenVolume'`.
  - `chain: ChainSlot[]` in real units. Only switched-on slots that carry the needed keys are tuned; a ReaFIR may be switched off and a switched-off Noise Removal on, as candidates like any other (below).
  - `render(changes)`: injected; renders the whole take with the changes (values, and slots switched on or off: `Change[]`) on top of the chain as it started, same length, aligned to the take. It is treated as expensive.
- **Measuring** (`measure.ts`): the raw take is analysed once with `analyze()`. Its speech frames, pause frames (the quiet lead plus the gaps between words) and speech windows are fixed, and every render is measured on those same frames. A gate or a noise remover therefore cannot change what counts as speech. Per render: speech level (median), peak and clipped samples, pause noise, SNR (speech − pause), level spread (analyze's consistency), share of dead digital silence, word loss (gain of the loud half of the speech frames minus that of the quietest quarter; above 2 dB a gate or remover is cutting words), and the speech spectrum in 6 cells per band.
  - **Speech cut by a gate** (`cutOf`, `TakeSummary.cutSpeech` / `cutEvents`): word loss is a median over 50 ms frames and read −0.7 dB on a result whose word starts were audibly chopped. So a gate is measured directly, against the same chain rendered with its gates passing everything (Wet off, Dry 0 dB): 10 ms frames over the speech and 150 ms before and after it (onsets and tails); a frame that carries voice (6 dB over the room in the ungated render) is cut when the gated render sits more than 3 dB under the ungated one, after the open gate's own gain. `cutSpeech`: share of the voice frames, each weighted by its depth (3 dB → 0, 20 dB → 1: a floor of Dry −6 turns a word start down, it does not cut it); `cutEvents`: runs of two or more frames over 8 dB under, per 10 s. The session keeps one ungated render per upstream state (`Session.refs`; the gate probe is one), so a gate move costs no extra render; an upstream move (EQ, compressor, level) leaves the kept value standing until `checkCut` renders it again. 0 without a working gate, NaN when no render was left for it.
- **The room is not the voice** (`measure.ts`): on the real take the room sits 12 dB under the voice and is broadband; at 640 Hz–2.5 kHz the speech windows are only 0.6 / 1.3 dB over the pause windows, so what was measured there as voice was room, and a remover that took it out read as 7 dB of tone damage. A band of the RAW take whose speech windows are not 3 dB over its pause windows is **masked**: NaN in every render of that take (no deviation, no score, not in the level match, not planned by the EQ). In the other bands the render's own pause spectrum is subtracted from its speech spectrum (never below 10 % of it). The subtraction uses the pauses as rendered, so behind a gate that closes on them it takes off less than the room that plays between the words. A raw take with less than 20 dB of voice over the room gets `unmet.room.loud` first in the list ("Your room noise is loud… lowering it at the source helps most").
- **Pumping** (`cutOf` → `pumpDb`): what a gate takes off the pauses of a room that is audible without it (less than 35 dB under the voice in the ungated render). Damage: 1.5 points per dB beyond 13, so Dry −20 over a loud room loses to Dry −12 or −6 (the doubled-gate fix steps to the shallower floor, `protectWords` repairs it like cut words). With a Noise Removal taking the room out there is nothing to pump and the gate stays as it was.
- **Noise Removal first** (`noiseRemovalOn`, before the gate and again after it and after compression): a remover that sits switched off is tried at strengths 0, 5, 10, one step and the amount's cap (counted from 0), one render each, lightest first, up to the first that reaches the target; the best-scoring one that wins 2 dB and passes the keep rule is kept. Pauses a remover turns fully silent are not damage while no word is cut: the run's targets allow dead silence from there on and the result says `unmet.silentPauses`. Real chain: strength 0 wins 2–7 dB, 5 about 12 dB, 10 takes the pauses to digital silence (20–29 % of the take), and that is what all seven goal sets keep, with ReaFIR off and the gate untouched (no cut, nothing pumped). The level trim after it can be held: the remover reacts to level (strong room noise ends 3.1 dB under the level target, said as `level.held`).
- **Tone** is the deviation of each band from the goal style's target (reference curve + style offsets), level-matched with the **median** of the seven speech bands instead of their mean. Up to three outlying bands (a deep low-cut, a boomy mic) cannot shift the others. `deviations()` in `src/audio/reference.ts` is unchanged for the website.
- **What the goals mean** (`targets.ts`):
  - use: streaming → SNR 30 dB, spread 8 dB · calls → SNR 25 dB, spread 10 dB (the call app removes noise and levels again) · recording → SNR 30 dB, spread 10 dB, pauses never dead silent.
  - style: the tone target.
  - roomNoise → SNR target 45 dB; with amount strong (not for recording) pauses may even go dead silent. The 45 dB is a wish for the noise stage, not a veto on the tone: the tone stage and its ReaFIR branch are judged against the use's own target (`snrFloorDb`, 30 dB, calls 25; `toneJudge`), so a tone fix may cost voice over the room while it stays there. Judged against 45, every dB cost 1.5 points and no cut of the loudest part of a voice was ever kept: the person in the noisy room kept the muddy voice. The result still lists the wish when it was not reached.
  - tooQuiet → speech target −19 dBFS instead of −21. unevenVolume → spread target 2 dB tighter and one more ratio step.
  - boomy / thin / muffled / harsh / sharpS / dull → their bands (boom+warmth high / low, mud high + presence low, presence high, sibilance high, sibilance+air low) are aimed 1.5 dB past the style target against the complaint, must come within 1 dB on that side (every other band: 3 dB) and count double. The same for lacksClarity (definition low, and what masks it: mud and warmth high), lacksPresence (presence low), lacksBody (warmth and body low), nasal (body high) and boxy (mud high).
  - amount caps every move, counted from where the chain started: one EQ band 2 / 4 / 6 dB (its gain; once its frequency or width moved, the largest change of its whole curve anywhere: a −4 dB band moved an octave away takes 4 dB off there and gives 4 dB back here), all EQ moves together three times that, Noise Removal strength 10 / 20 / 40 per step and 20 / 40 / 80 in total, gate threshold 5 / 10 / 20 dB, compressor ratio up to 2 / 3 / 4. The level make-up is not capped by the amount (only by 0..18 dB Wet and the peak ceiling).
- **Score** (`score.ts`, penalty points, 0 = nothing left to fix):
  - level: 1 per dB the speech is off the target beyond 1 dB, 3 per dB the peak is above −1 dBFS, 15 when samples clipped. Between stages only what the final trim cannot repair counts, so an EQ cut or a compressor is not rejected for level the trim gives back.
  - noise: 1.5 per dB of SNR under the target, the SNR counted from 0 to 45. No cap on the points: capped at 45 (the clarity score's cap), a noisy take 30 dB under the 45 dB "room noise" target lost nothing for every further dB, and a compressor lifting the room 2.5 dB was kept for exactly the person who asked for less noise.
  - tone: 1.2 per dB a band is outside its tolerance (air counts half, rumble not at all, complained-about bands double).
  - consistency: 1.5 per dB of spread above the target.
  - damage: up to 35 for dead digital silence (from 5 % zero samples or 6 cut-outs per 10 s), 3 per dB of word loss above 2 dB, and, when measured, 8 per percent of speech cut by a gate beyond 1 % plus 3 per cut event beyond 1 per 10 s. Damage never gets the keep rule's extra share, so no voice over the room pays for cut words.
  - **Keep rule:** a candidate is kept when the total drops by at least 0.5, no other part gets worse by more than 1.5 points plus a quarter of what the change wins on its own part (all of it for the level and the final trim: a plugin after the gain stage that reacts to level, like Elgato Noise Removal, moves the other parts on its own; damage never gets that extra), and the stage's own measured effect is there (below). Otherwise the kept state and its render stay as they were.
- **Stages, in order** (`stages.ts`, `toneStage.ts`, `switches.ts`):
  0. **A ReaFIR that cuts the voice** (before the level, counted as `baseline`): the chain as it is loses words (word loss above 2 dB), leaves dead silence or no voice at all, and a ReaFIR is on → ReaFIR off, kept when the damage really went away. A noise profile that does not fit the take subtracts the voice with the room, and no value of the other effects brings it back (`_test/no-filters.wav`: speech −44 dBFS, 15.6 dB word loss, 17.6 % dead silence → −28.8 dBFS, −0.1 dB, 0 %).
  1. **Level:** the last switched-on ReaComp's Wet moves the speech toward the target, never lifting the peak above −2 dBFS. Kept when the speech got at least 0.5 dB closer and nothing clipped. A second pass corrects by the measured slope when the chain answered with less than asked. A working ReaGate after that ReaComp moves its threshold by the same dB in the same render, so it keeps closing on the pauses and opening on the words (`reason.level.gateFollows` when its threshold had not moved before).
  2. **Noise & gate:** doubled ReaGate → Dry −20, plus a threshold where it closes when it opens on every pause it receives (kept when SNR rises 1 dB). Damage first: dead silence from a hard gate (Dry ≤ −40 dB) → Dry −20; else Noise Removal one step lighter, then as light as the amount allows; else gate Threshold 10 dB lower (not under −72). Then, without damage and under the SNR target: Noise Removal one step stronger (half a step when the full one damaged the voice), repeated while it helps; a gate under its threshold for what it receives is raised to it. A noise move needs 2 dB of measured SNR.
     - **A gentle gate, no cut words** (`protectWords`): the doubled-gate fix tries Dry −20 first and a shallower floor (−12, then −6, with hold ≥ 300 ms and release ≥ 400 ms) only when the deeper one cut speech. After the noise stage, and again on the final state after the trim, the kept gate is measured against the ungated chain; while it cuts speech (more than 1 % or 1 event per 10 s) gentler versions are rendered, one render each: its threshold 1, 2 and 3 dB lower (in a noisy room the place that closes on the pauses without cutting word starts is a dB wide), Dry −12, Dry −6, and in a second round a longer hold and release. Of those that no longer cut, the one with the best score is kept (the most voice over the room that leaves the words whole); when none does, the one that cuts least. What it costs in voice over the room is not asked, the use's own target included; the result then says `unmet.noise.wouldCut` ("More noise reduction would start cutting your words…") instead of the plain room line, and `unmet.cut` when a gate still cuts. The level is trimmed once more after a floor change. The two ReaFIR branches are compared without the cut term: the final gate is made gentle afterwards in either.
     - **What a gate receives:** without a ReaComp before it, the raw take's levels and the guide's threshold (30 dB under the speech behind a noise remover, else just over the room). Behind a ReaComp (the noisy-room chain … → ReaComp → ReaGate) the raw levels say nothing, so they are read from a render minus the gate's own gain, when nothing after the gate removes noise and the gate passes everything there (or never closes). ReaGate opens on sample peaks (RMS size 0, as the guide leaves it), so the threshold goes 70 % of the way from the pause peaks (P90 of the pause frames' peaks) to the quiet syllables' peaks (P10 of the quietest speech frames' peaks), but stays 2 dB under those and at least 0.5 dB over the pause peaks. Nearer the syllables because the hold keeps the gate open through a phrase, while every pause peak over the threshold holds it open. The amount caps the move from where the gate starts to act (the pause peaks), not from a threshold that never closed.
     - **Noise Removal sitting switched off** (after the noise stage, and again after compression): when the voice over the pauses misses the target by 1 dB, nothing is damaged and no Noise Removal is on, one that sits in the chain switched off (Wave Link bypass, or its own bypass) is switched on at the lightest strength that wins 2 dB (0, one step, the amount's cap, counted from 0, not from the value it was stored with; the next one only while the one before removed too little), then stronger while it helps. The keep rule judges it like any noise move, so a remover that costs the voice its tone or its quiet words is switched back off and not asked again in that run. On the real chain Elgato Noise Removal behind ReaComp brought the room to 46 dB under the voice at strength 0 and took 7 dB out of 640 Hz–2.5 kHz at any strength: not kept.
     - **Moves upstream of such a gate** (tone, compression): when one is rejected and its render lost 6 dB of voice over the pauses (the gate opened), one probe render with the gate passing everything reads what it now receives, and the move is tried again with the gate's threshold raised to match.
  3. **Tone:** only bands the chain has (enabled Low Shelf / Band / High Shelf of a switched-on ReaEQ, no notches), inside the guide's gain ranges. The plan is solved on the take's own spectrum with each band's nominal curve (`eqModel.ts`), gains first: the least EQ that brings the bands inside their tolerances, never lifting healthy bands to hide a loud one (the matching level is frozen while planning), never pushing another band more than 0.75 dB further out, each band moving at least 1 dB or not at all and at most 1.5 times what the bands it reaches need, and never against a complaint (boomy: no lift on a band that reaches boom or warmth; dull: no cut on the top). The plan is rendered. From that render the tuner fits how much of its curve each moved band **really** produced and plans again with those strengths: a band that did nothing or the opposite is dropped, a weak one is pushed or replaced. A new plan replaces the kept one only when it measures better. Kept when the tone score improves and no band ends more than 1 dB further outside its tolerance, read with the after render matched at the before render's level shifted by the median gap between each band's measured and predicted change: what the plan meant reads as planned and only what the EQ did beyond it counts (re-matching each render on its own median made a 250 Hz cut that reached the median band read as presence 2 dB higher; a fixed level read the compressor after the EQ giving the level back as every band rising). S sounds are judged on the measured 5–10 kHz band like any other; when nothing in the chain moves it enough, the result says so and suggests a De-Esser or a band at 6–7 kHz. In a noisy room (SNR under 25 dB) a band with less than 12 dB of voice over the room is never boosted; a shelf counts every band past its corner (a 150 Hz low shelf lifts the rumble under it). A plan that cost 1 dB of voice over the pauses is planned again with no gain rising above where the chain had it on such bands (un-cutting lifts the room like a boost).
     - **Shape** (`planShaped`): while the gains alone leave 2 dB of weighted excess, a band's frequency and width may move too, so a narrow cut can sit on a hump without thinning the hole next to it and a lift can be put where the voice is missing. Candidates: a Band on the centre and the lower / upper part of each of the (up to three) worst bands it can reach within one octave of where the chain has it, inside 80 Hz–8 kHz, at 0.5 / 1 / 1.5 oct or its own width (always within 0.3–2.5 oct, so it never becomes a notch); a shelf stays a shelf and only its corner moves, half an octave or an octave (60 Hz–12 kHz). Each candidate is re-solved with all gains; the one whose plan costs least is taken when it beats the plan so far by more than 2 dB of excess (each reshaped band costs that much on top of the dB it moves), at most two bands per plan. A moved band answers for every tone band its curve reaches at its new place, from 0 dB: a cut it carried is not taken along onto a band the person hears as too little, nor a lift onto one they hear as too much or where the room is loud, and a band that may not be lifted (or cut) where the chain has it may not be either once moved. Rendering, the fit of what each band really did and the keep check work on the moved shapes like on gains. One moved band is one change for the person: "ReaEQ Band 3: 450 Hz, 1.2 oct, −1.5 dB → 226 Hz, 0.5 oct, −4.5 dB" (`desktop.autotune.change.band`).
     - **With or without ReaFIR** (`toneWithSwitch`): when a ReaFIR is on and the tone reached with it still scores 3 points or more, the other branch is rendered too, from the state before the tone stage: ReaFIR off (one render; when a gate behind the compressor opened on the pauses for it, the gate's threshold is placed again), Noise Removal on in its place when the room then misses its target (its own keep rule), and the tone stage again on what the voice measures without it. The branch replaces the first result only when its measured score beats it by the keep rule; otherwise everything goes back to the first result. Both ends are rendered, nothing is kept on a prediction.
     - **The noise stage's second go** (`roomTouchUp`): a tone plan that is rejected and ends under the use's own target, having lost 1 dB or more of voice over the pauses, is tried once more with the gate behind the compressor placed for what it now receives. After the tone stage (each branch, before the branches are compared) and after compression, when the voice over the pauses sits under that target the gates are placed again (one probe render; kept when it wins 2 dB), and a switched-off Noise Removal is tried as above.
     - **When nothing could be kept because of the room:** cutting the loudest part of a voice makes the whole voice quieter against the room. When every rendered plan was rejected and even the gentlest cost 1 dB or more of voice over the pauses, the result says so (`unmet.tone.room`) next to the bands that stay out.
  4. **Compression:** when the spread is above the target, the last ReaComp gets the amount's ratio (if lower) and a threshold 6 dB under the speech level it receives (−45..−12 dB); a second pass goes 4 dB lower. Kept when the spread narrowed 1 dB; room noise it lifts into the pauses counts against it.
  5. **Final trim:** the level stage again, after the other stages moved the level.
- **Budget:** 40 renders by default (`maxRenders`; a render costs 0.25–0.9 s): 1 for the chain as it is (2 when a gate already works: its ungated reference), then at most 2 / 14 / 8 / 3 / 10 per stage (the trim's share covers the final gate check and its gentler versions) (noise includes the switch candidates and their gate probes; tone covers both branches, 4 plans each), one always kept back for the final trim. The real chain used 14–26 (2.5–9 s). A candidate rejected once is not rendered again from the same state. An already-good take costs one render. When a stage has no render left, the result lists `unmet.budget`.
- **A render without a voice** (an effect cuts everything) is judged only on getting the voice back; if nothing in reach does, the result is `unmet.silent` and no change.
- **Result:** `TuneResult { changes: TuneChange[]; before; after: TakeSummary; processed: Float32Array; renders; unmet: Msg[]; log; goals; limit }`. Each `TuneChange` is a `Change` (a `ValueChange`, or a `SwitchChange`: a slot switched on / off, no from / to numbers; the engine adapter applies either as is) plus `stage`, the reason (`titleMsg`), the exact change line (`changeMsg`: "ReaComp Wet 6 → 14.5 dB", "ReaFIR off") and `effect { metric, band?, before, after }`: the metric it was made for, right before the change and in the final render. A ReaEQ band whose frequency or width moved is one change (its gain, or the first value that moved) with the band's other moved values in `also`; `engineChanges(changes)` is the flat list the render and Save take, `valueChanges(changes)` the flat value changes. `unmet` says what could not be reached and why (no EQ / no compressor / nothing to remove noise with, Wet at its limit, peaks in the way, a Wet move that made the rest measure worse, nothing reaches that band, more would damage the voice, the EQ fix cost more voice over the room than it won, budget used up).
  - **A complaint the measurement contradicts** is said, not skipped: what the person describes points at too little of a band that measures 1 dB or more over its target ("lacks presence" with presence at +3) → `unmet.tone.hidden` when a band under it stands 4 dB or more over its target ("…already measures 3.2 dB above your target, so it was not lifted further. What hides it is too much 160–320 Hz…"), else `unmet.tone.alreadyHigh`; too much of a band that measures under its target ("boomy" with 80–160 Hz at −6) → `unmet.tone.alreadyLow`. These replace the bare "still above / under your target" line for that band. Strings: `desktop.autotune.reason.*` and `desktop.autotune.unmet.*`, en + pt-BR.
- **Retune:** `tune({ take, chain, render, ...retune(result, feedback) })`.
  - `'tooProcessed'`: one amount lighter (on the lightest: all caps halve), and every change except the level starts halfway back to where the chain was.
  - `Bother[]` (what still bothers them): added to the goals; the run starts from the previous changes and render. A bother that was already a goal means "more": the halved caps come back first, else the amount goes one up.
  - A start is kept only if it still beats the untouched chain under the new goals. A switch starts as it was kept; "too processed" leaves it and brings a moved band halfway back as a whole (frequency and width with the gain).
- **Real chain** (`renderer.ts`): `openTuneSession(bridge, take)` → `{ chain, render, exportChanges(changes), close }` over the offline render session. `chain` is `chainOf` of the session's slots and the mic input's Wave Link entries (the input whose entries match the slots by index and name; it rejects and closes the session when none does), with a slot off when the plugin's own bypass is on (`ownBypassOn`: the stored Noise Removal state has Bypass = 1 while Wave Link lists it on, so it passes audio through and its strength does nothing). `render(changes)` puts the session's plugins at the baseline plus `changes` (only values and switches that differ from the last render are sent, through the live screen's `engineOp`: a switch is `render_set_bypass`, sent before the slot's values and sent back when a later render does not list it; a value back at the baseline gets the plugin's own parameter value) and runs the take. `exportChanges` takes a result's changes as they are (`also` included), applies them, reads `renderExportStates` and returns `exportPlan`'s Wave Link changes against the chain as Wave Link lists it: a VST2 slot switched off or on is its `BypassState`; a Noise Removal taken off its own bypass is its exported `ParameterState`, which carries that bypass (Wave Link already lists it as on, so the session marks it as changed). Calls are serialized.
  - Checked with `tools/tune-real/run.ts` (render_cli, a Settings.json copy, `_test/control-2-cm-raw.wav`): the stored chain (ReaFIR → ReaEQ → ReaComp Wet +18 → doubled ReaGate at −58 dB → Noise Removal on its own bypass) peaks at +6 dBFS with the room 15 dB under the voice. The tuner brings the speech to −21 dBFS (peaks −5 to −7), turns the gate behind the compressor into an expander at Dry −20 (voice over pauses 15 → 31–35 dB, no dead silence, no word lost), compresses where the room allows and makes small EQ moves; 7–8 renders, about 2 s. With gains only, the 160–320 Hz excess (+11.5 dB) stayed beyond a 1.5–2 dB cut, because a deeper cut would push 80–160 Hz (already 6 dB low) further down.
  - What ReaFIR does there (measured alone on that take): 80–160 Hz of the voice −15.4 dB, 40–80 Hz −37 dB, every band above −0.6 to −2.2 dB, speech −2.7 dB, pauses −4.5 dB: 1.7 dB more voice over the room, and a hole right under the close mic's own hump (the raw take already measures +9 dB at 160–320 Hz). With switches and shapes (default goals, 14 renders, about 4 s): ReaFIR off, Low Shelf 150 Hz −4, Band 250 Hz −4, Band 3 from 450 Hz / 1.2 oct / −1.5 dB to 226 Hz / 0.5 oct / −4.5 dB → 160–320 Hz +12.5 → +2.2 dB, 80–160 Hz −6.6 → +3.8 dB, voice over pauses 29 dB (the result says 30 was not reached), peak −3.6 dBFS, no dead silence, no word lost. Keeping ReaFIR and placing two narrow cuts on the hump measured +7.1 dB there and scored worse (31.0 against 26.6 for "lacks clarity + lacks presence"). With "room noise" picked (45 dB wanted) the tone is fixed all the same: boomy + room noise keeps ReaFIR and places two narrow cuts on the hump (160–320 Hz +12.5 → +5.4 dB), strong room noise switches ReaFIR off (+3.3 dB); both end with the voice 28.6 dB over the pauses (35.6 before the tone fix), 1.4 dB under the use's own 30: the gate behind the compressor finds no better threshold there (pause peaks and quiet syllables 2 dB apart) and Noise Removal costs the mids, so the result lists the room as not reached.
  - Words cut by the gate (heard on the clarity result, where word loss read −0.7 dB): with the threshold 70 % of the way up, the cut measure reads 1.4–3.0 % of the speech and 1.8–4.5 cuts per 10 s over the goal sets. With the gentle gate: 0.2–0.9 % and 0–0.9 per 10 s, the threshold 1–2 dB lower (Dry stays −20; boomy + room noise takes Dry −12), voice over the pauses 27.8–30.2 dB (boomy + room noise 21.8) instead of 28.6–31.1, tone unchanged.
- **Tests** use a small fake chain (`fakeRenderer.ts`: block noise remover and gate, RBJ biquads, feed-forward compressor, a ReaFIR that is a 24 dB / octave low-cut at 170 Hz unless a test gives its own, slots switched on / off) and synthetic takes with a chosen spectrum (`testTake.ts`). What the fake does not do: plugin latency or pre-ringing, a noise remover that changes the voice's own spectrum or needs time to settle, ReaComp's knee / RMS window / auto make-up, level-dependent effects after the compressor, and ReaEQ curves that differ from the RBJ ones. `realChain.test.ts` pins what the real chain showed: shelves and the no-boost rule, moves against a complaint, the aligned tone check, and when a gate's input can be read from a render; `tune.test.ts` covers a gate behind a compressor; `switches.test.ts` the switch candidates (kept when they help, switched back when not), a band moved onto a hump next to a hole, the caps on a moved band, complaints the measurement contradicts, an EQ fix that costs the room, determinism and the budget.

### Tune from a recording — screen
The desktop app's main screen (`#/desktop`, the screen it opens on): "record, say what you want, the app tunes your real effects on that recording, compare, save". The live screen stays as the secondary "Fine-tune live" page (`#/desktop/live`, Screen `desktopLive`, desktop app only). A tab nav at the top of both pages switches between "Tune from a recording" and "Fine-tune live". Title "Make your mic sound better" with a one-line subtitle. Code: `src/components/desktop/autotune/` (hooks + components), pure helpers in `src/desktop/autotune/`.
- **A stepper, one step visible at a time** (at phone width only the current step is named):
  1. **Record your raw mic.** Microphone picker (no output; the engine runs with the monitor Off). "Start recording" starts `audio_start`, collects `AudioFrame.raw` into one 48 kHz take (`TakeRecorder`): "Stay quiet…" countdown for the first 3 s, then the reading text (the wizard's passage, then "keep talking until the bar is full"), a progress bar (seconds of 25) and the mic level. It stops by itself at 25 s; Stop is offered from 12 s. The engine is stopped when the take ends. Frames lost on the way (`counters.streamDropped` or `inputOverruns` went up) → "record again". A take is checked with the tuner's own frame split (`checkTake`: clipped samples, sound in the quiet lead, under 10 s, silent / too quiet / noisy pause from the web check's reasons, under 5 s of speech frames); a failed check shows a plain message and "Record again". Alternative: "Use a WAV file" (`decodeWav`: PCM 16/24/32-bit or float 32/64, mono or stereo, extensible header; channels averaged, linear resampling to 48 kHz, at most 30 s, under 10 s refused), then the same check.
  2. **What do you want?** Chips: Used for (Streaming / Calls / Recording), Sound (Natural / Warm / Clear / Bright, the style names), What bothers you (any of Room noise, Boomy, Muffled, Thin, Harsh, Sharp S sounds, Dull, Too quiet, Uneven volume), Processing (Light / Medium / Strong). The last choices are stored in localStorage `vcb-autotune-goals` (validated; defaults when storage is blocked). "Tune my effects".
  3. **Tuning.** Settings.json is read (the hash Save checks), then `openTuneSession(bridge, take)` and `tune()` with `onProgress`. The five stages (Level, Noise and gate, Tone, Compression, Final level) show Done / "Pass n of m…" (renders of that stage so far of its `STAGE_RENDERS`) / Waiting; before the first stage, "Listening to your recording through your effects as they are now…". Cancel stops waiting for the run, closes the session and goes back to step 2. Errors (no Wave Link chain, a plugin failing) in plain words (`desktop.errors.*`) with Try again.
  4. **Listen and save.**
     - Before / After on the SAME take through Web Audio: the raw take vs `result.processed`, clamped to ±1 for playback; one plays at a time; switching sides while playing restarts the other at the same position, so A/B is instant.
     - "What changed": voice level, loudest moment, room noise in pauses, voice over room (SNR), steadiness (spread), and each tone band that moved ≥ 1 dB (distance from the goal's target), before → after with Better (success) / Worse (error) / About the same (neutral). Voice level is judged by distance to the goal's speech target, the peak only near clipping (above −1 dBFS), changes under 0.5 dB count as the same.
     - "N changes, each with its reason" (collapsed): the reason, the exact change in bold, the measured effect before → after. A switched slot reads "ReaFIR off" / "Elgato Noise Removal on"; a ReaEQ band whose frequency or width moved is one line with all three of its values before → after.
     - "What it could not do": the tuner's `unmet`, 4 shown, "Show all".
     - Buttons: "Save to Wave Link" (the session's `exportChanges(result.changes)` → the live screen's preview / confirm / force / verify dialog with the hash read in step 3), "Not right, adjust" (chips: Too processed, or the bothers → `retune()` → step 3 on the same take and session), "Record again" (closes the session). No changes: "Your sound already meets these goals" and Save is disabled. After a save: a confirmation with a "Fine-tune live" link.
